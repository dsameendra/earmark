Brand asset specification (T32)
  • App icon. Icon Composer document with layers: squircle background (gradient #E8794A → #C44B16 → #8F360E), ear (cream stroke), arc (#FFD7BF), curl (shaded corner triangle plus folded flap, 28% of the tile). Geometry on the 100-unit grid is in Main.dc.html: ear path with stroke 4.8, group transform translate(12 16) scale(1.15) (this is the locked left-2.5% offset), arc M44 20a15 15 0 0 1 0 20, curl triangle M72 0H100V28Z, flap M72 0V24a4 4 0 0 0 4 4H100Z. No baked gloss or shadow.
  • Appearances. Default (Ember), Dark (night tile, cream ear, #F28A57 arc and flap), Tinted and Clear as Icon Composer derives them. Check legibility at 16, 32, 64, 128, 256, 512, 1024.
  • Menu bar glyph. Template image of the ear and arc only, 18 pt, monochrome. Recording state adds a small red dot (#D1352B) bottom-right, never Ember. Idle shows no dot.
  • Symbols. 24 symbols in Icons.dc.html (asset names shown on each tile) plus the ear glyph (the app mark at symbol size); ink line plus one Ember detail; Ultralight-Black, small/medium/large; monochrome, hierarchical and palette rendering; fall back to stock SF Symbols if a custom glyph fails review.
  • Marketing/DMG. Newsreader wordmark earmark lowercase, lockups in Main.dc.html; Ember on paper or cream on night.
Caveats and how they are resolved
CaveatResolution
Web fonts stand in for New York and SF Pro in the boardsSpecified as real system fonts in the type table (Handoff 1). Build with system fonts; do not bundle Newsreader.
Symbols are web approximationsThe path data in Icons.dc.html is the authoritative geometry; T33 redraws on the SF Symbols template and must pass a side-by-side weight check against SF at each weight.
Custom duotone is the least native symbol optionAccepted by the user. Mitigation: palette rendering, matched weights, stock-symbol fallbacks, and a T33 review gate.
Glass API names may differ in the shipping SDKMapping is stated as intent. The T31 spike confirms real API (glassEffect, GlassEffectContainer, glass button styles) and records results.
Copy and data are illustrativeReal strings come from the feature specs and localisation. Names, durations and quotes in boards are placeholders.
Not every screen is drawn in both appearancesEditor is dark (light in Components.dc.html), the rest are light. Both appearances use the same tokens (Handoff 1); build both and snapshot-test each.
Mockups are 1440 x 900Responsive.dc.html shows narrow, compact and wide windows. Minimum window 960 x 600; below 1100 pt hide the Editor inspector behind a toolbar toggle; below 800 pt collapse the sidebar.
Contrast was checked by calculation, not in a rendered buildT40 verifies every token pair at AA in both appearances, plus Increase Contrast.

Kickoff gate for M8 (mandatory)
  1. Before any M8 work, ask the user for the Claude Design canvas link. Do not assume access from a previous session.
  2. Read it with the Artifact tool (action: "read"). Confirm it is the final design: the board Handoff 1 shows "Final design v1" and the canvas title reads "Final v1".
  3. Compare against the repo copy in specs/design/m8-mockups/. If they differ, stop and ask the user which is authoritative.
  4. Read specs/design/m8-handoff.md and specs/design/m8-ui-overhaul.md in full.
  5. Run the T31 spike on glass APIs and symbol weights; record findings in specs/design/m8-spike.md before building screens.
