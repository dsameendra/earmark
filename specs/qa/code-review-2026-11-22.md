# Code review, 2026-11-22

Scope: `git diff 91850b0..HEAD -- Packages App NativeRuntime scripts project.yml` (213 files, about 20.7k added lines). Read-only static review; nothing was built or run, so findings marked "probable" need a runtime check. Every finding below was verified by reading the cited code; speculation was dropped (the few kept are labelled).

Severity scale: High = user-visible data loss, privacy breach or broken core feature. Medium = real defect with a plausible trigger. Low = narrow window or cosmetic consequence.

Note on the "58 @unchecked Sendable" figure: in git-tracked non-test sources under `Packages/*` and `App/` there are 30 uses (the rest of the 58 are in tests or in vendored `.build/checkouts`). All 30 were looked at; see the end of "Confirmed bugs" for the audit.

## Confirmed bugs

### B1. Meeting audio cannot be played back: wrong library root (High, probable, strong static evidence)
- `Packages/Features/Sources/FeatureEditor/Playback.swift:289-300` (`MediaLocator.defaultLibraryRoot` = `Application Support/Earmark/Library`), called without a root at `TranscriptEditorModel.swift:229`.
- Recordings are written under `<libraryLocation or Application Support/Earmark>/Meetings/<folder>/` (`App/MeetingRuntime.swift:53-64`, `MeetingSessionController.swift:187-193`). The session's `relativeDirectory` is just `<folder>`, so the library-owned `MediaAsset.libraryRelativePath` is `<folder>/mix.m4a` (`MeetingFinalizer.swift:355-359`).
- Failure: `MediaLocator` resolves `<folder>/mix.m4a` against `Earmark/Library`, finds nothing, has no bookmark for library-owned assets, returns nil, and the editor shows "media missing" for every meeting transcript. A custom `storage.libraryLocation` or `meetings.storageLocation` is ignored as well. The unit tests hide this because they use `relativeDirectory: "Meetings/x"` with a base root (`FinalizerTests.swift:23,81`, `RecorderTests.swift:81-87`), a different convention from production.
- Fix: pick one convention (store the path relative to a single documented root, including the `Meetings/` segment) and inject the same root resolver into `MediaLocator` from the composition root. Add an integration test that records, finalizes and then resolves via `MediaLocator`.

### B2. "Delete Permanently" and auto-purge never delete recordings or media files (High)
- `LibraryModel.swift:240-250`, `SQLiteTranscriptRepository.swift:140-160`, `SQLiteRepositories.swift:43-57`. Repo-wide, no `removeItem` touches user media or recordings (only model files, temp files and the DB backup).
- Failure: purge deletes the transcript rows and only soft-deletes the library-owned `mediaAsset` row (`softDelete` sets `deletedAt`). The CAF/M4A/MOV files of meeting recordings (audio of other people's voices, plus optional screen video) stay on disk forever and become invisible orphans. `purgeDeleted(before:)` (LIB-AC-08, run at launch and daily) does not even look at assets. The `Meeting` row is not purged either. For a privacy-first app this contradicts LIB-AC-09 ("purge transcript, segments and library-owned media").
- Fix: on purge (both paths), resolve each library-owned asset and meeting recording folder, delete the files (only when `isOwnedByLibrary`; never user-referenced originals, LIB-AC-12), then hard-delete the asset and meeting rows. Make it idempotent so a crash between the DB delete and file delete is retried by a sweep for orphans.

### B3. Launch-time recovery can hijack a recording that is in progress (Medium)
- `App/AppEnvironment.swift:97-101` starts `detector.start()` and then `MeetingRuntimeFactory.recover(...)` in the same task; `MeetingRecorder.swift:337-361` treats every manifest whose `state != .finalized` as interrupted, including `state == .recording`.
- Failure: launch the app while a Zoom/Teams call is live with auto-record on. The detector fires, the session creates its folder and `meeting.json`, and the concurrently running recovery scan picks that folder up, runs `CAFTrackRecovery.repair` on files being written, mixes, deletes the track files when `keepSeparateTracks` is false, and marks the manifest `.finalized`. The live recorder then keeps appending to files the recovery has repaired or removed. A second window: a `.stopped` manifest (mix failed) whose finalize job is already running is finished again concurrently by `RecordingRecovery` and by `MeetingFinalizer.run` (`MeetingFinalizer.swift:162-165`), both writing `mix.m4a`.
- Fix: run recovery to completion before `detector.start()`, and skip directories that belong to the active session (`controller.currentSession`) or that already have a pending/running `.finalizeMeeting` job.

### B4. `MeetingSessionController.startSession` is not reentrancy-safe (Medium)
- `MeetingSessionController.swift:148-180`: `guard active == nil` is checked, then there are many `await`s (`meetings.save`, `consent.needsNotice`, mic and remote `start()`, `recorder.start`, `live.start`) before `active = state` at line 180.
- Failure: two entries into `startSession` inside that window (detector `.started` auto-policy plus the user answering a prompt or pressing Record; or two apps) both pass the guard, both start a mic source and a recorder. The second overwrites `active`, so the first mic tap, recorder and helper tasks are never stopped and keep writing files. `MeetingCaptureAdapter.start` (`App/MeetingRuntime.swift:152-162`) has no guard either.
- Fix: set a `starting` flag (or reserve `active` with a placeholder) synchronously before the first `await`; reject or queue concurrent starts.

### B5. Qwen ASR: the one-at-a-time gate is released before the MLX task actually stops (Medium, probable)
- `QwenSinhalaEngine.swift:145-153,158-172` and `MLXQwenRecognizer.swift:36-57`. `recognize()` runs generation in a `Task.detached` whose cancellation is only observed between tokens; `collect` returns (loop guard `break loop`, cancellation, or error) and `defer { release() }` hands the gate to the next utterance while the previous detached task may still be inside a token step on the same non-thread-safe `Qwen3ASRModel`/KV cache.
- Failure: cancelling a file job or the live session mid-utterance, or a repetition-loop break, followed immediately by the next recognition (the engine instance is shared by file jobs, live captions and dictation) can overlap two generations on one model: data race, garbage text or a crash in MLX.
- Fix: make the stream wrapper await the detached task's completion (for example `await task.value` in `onTermination` is not allowed, so expose `recognize` as an async function that awaits `task.value` in a `defer` before returning) so `release()` only happens after the generation task has finished.

### B6. NLLB worker: write to a dead worker's stdin can raise SIGPIPE and kill the app (Medium, probable)
- `Packages/Translation/Sources/EarmarkTranslation/NLLB.swift:244` (`try stdin.write(contentsOf:)`). Nothing in the repo ignores SIGPIPE (`grep -rn "SIGPIPE\|signal(" App Packages/*/Sources` is empty) and the pipe has no `F_SETNOSIGPIPE`.
- Failure: the helper is OOM-killed or crashes between requests; `Process.isRunning` lags the exit, `startWorker()` sees it as running, the next `write` hits a closed pipe and the default SIGPIPE action terminates Earmark. Cancellation (`read`'s `onCancel` calls `terminate()`) opens the same window for the next request. Swift's `throws` on `write(contentsOf:)` does not help if the signal is delivered first.
- Fix: `signal(SIGPIPE, SIG_IGN)` at launch (or `fcntl(fd, F_SETNOSIGPIPE, 1)` on the pipe's write end) so the write returns `EPIPE` and the existing catch restarts the worker. Please confirm at runtime with `kill -9` on the worker between two translations.

### B7. Crash recovery marks the manifest finalized before the meeting is saved (Low-Medium)
- `MeetingRecorder.swift:319` (`manifest.state = .finalized` inside `RecordingFinisher.finish`) then `:357` (`try? await meetings?.save(meeting)`).
- Failure: if the DB save fails (or the app dies right after `finish`), the manifest is already `.finalized`, so `interruptedDirectories` never returns the folder again and the recording has no `Meeting`/transcript: invisible data, and no finalize job. `try?` also hides the error.
- Fix: make the manifest `.finalized` only after the meeting row is saved, or give recovery an "orphan sweep" that creates meetings for finalized folders that have none.

### B8. `MeetingRecorder.stop()` can drop the video track from the manifest (Low)
- `MeetingRecorder.swift:140-150` takes `var manifest` into a local before `await drainConsumers()`; `startVideo` (`:120-137`) resumes during that await (actor reentrancy, state is still `.recording`), sets `videoRunning = true` and appends the video track to `self.manifest`, but `stop()` later writes and finishes with its stale local copy.
- Failure: Stop pressed while ScreenCaptureKit is still starting leaves `video.mov` on disk but absent from the manifest and `Recording`, so it is never listed, played or purged. Narrow window (first second or so of a recording).
- Fix: re-read `self.manifest` after the `await`s in `stop()` (or serialise start/stop with a state enum that has `.starting`).

### B9. Batch bookkeeping registered before the inserts it describes (Low)
- `PersistentJobQueue.swift:78-84`: `batches[batch]`/`batchOf` are populated, then `for job in created { try await insert(job) }` can throw part-way.
- Failure: a storage error on job N leaves jobs 1..N-1 persisted and pending but the batch's `remaining` set includes ids that never exist, so `batchFinished` never fires and the member jobs' individual notifications are suppressed (`jobReachedFinalState` returns early for batch members).
- Fix: build the `BatchState` from the ids actually inserted (or insert first, register after).

### B10. Model download: no path-traversal guard on remote file paths (Low)
- `ModelStore/ModelManager.swift:404,462` append `file.relativePath` (from the Hugging Face tree JSON, `Downloading.swift:~147-155`) to the payload folder without rejecting `..`, absolute or empty components. Host allow-listing and HTTPS limit exposure, but a compromised or hostile repo could write outside the model folder.
- Fix: reject paths with `..`/leading `/`, and assert the standardized destination has the payload folder as prefix.

### B11. Dictation: release or cancel during `ensureAccessibility()` is dropped (Low)
- `DictationController.swift:244-262`: `phase = .listening` is claimed, then `await ensureAccessibility()` runs before `session` exists. `.finish`/`.cancel` events arriving in that gap hit `guard phase == .listening, let s = session` and are ignored (`:177-182`, `:190-197`), after which the session starts anyway.
- Failure: a quick accidental tap (DICT-AC-13) or push-to-talk release in that gap leaves dictation listening (mic open, HUD up) until the next press. The window is short when permission is already granted.
- Fix: record a pending-stop flag during the claim phase and honour it right after the session is created.

### @unchecked Sendable audit (30 uses)
- Sound as written (lock or atomics, or confined to one serial queue): `RingBuffer` (documented SPSC with acquire/release), `AudioRenderSink`, `ScriptedCaptureBackend`, `AudioDeviceProvider`, `HAL.Listener`, `AudioListenerHub`, `FrameWriter` (queue-confined; `finish()` syncs on the queue first), `ScreenCaptureVideoRecorder` (unfair lock), `CGEventTapHotkeySource`/`NSEventHotkeySource`/`FallbackHotkeySource` (NSLock), `Transfer` (unfair lock), `DeadlineRace`, `BaseTime`, `LineBuffer`, `SourceBox`/`ObserverBox`, `ManagerBox` (read-only after init), `WhisperHandle` (serialised by `AsyncGate`), `SCKAudioOutput`, `AVAudioEngineBackend`/`ProcessTapBackend`/`ScreenCaptureKitBackend` (mutable state is only touched through the `CaptureSession` actor's serialised start/stop/restart; documented in comments).
- Not sound or only conditionally sound: `MLXQwenRecognizer`/`ModelBox` (see B5); `LineReader` in NLLB.swift (single-consumer by convention; safe only because `CTranslate2WorkerRuntime`'s gate serialises it).
- Unnecessary (could be checked `Sendable`, which would let the compiler police them): `SystemMeetingPrompter` (only an immutable `let bus`), `SystemPasteboard` (stateless), `SuppliedFlag` (used inside a synchronous converter block; a local box is enough).

## Spec gaps

Verified by reading code and grepping tests. "Test gap" means the behaviour exists but no test names the AC.

1. **LIB-AC-13 storage breakdown and library location change: not implemented.** `StorageSettingsView` (`FeatureSettings/PreferenceViews.swift:467-495`) shows only the models total plus a static library-location label. No sizes for library, recordings or caches, no picker, no move/confirm flow. `storage.libraryLocation` is only read by `MeetingRuntime.recordingsRoot` (it moves the Meetings folder; the SQLite DB is hard-wired to `Application Support/Earmark/earmark.sqlite`, `AppEnvironment.swift:351`). The `clearCaches` action deletes `~/Library/Caches/lk.dumindu.earmark/*`, but nothing in the repo writes there, so "Freed 0 bytes" is the typical result.
2. **LIB-AC-09 / LIB-AC-08 media purge:** see B2.
3. **FILE-AC-04 per-file overrides: not implemented.** `BatchSettingsModel.submit()` (`FeatureQueue/BatchSettingsModel.swift:190-205`) sends one `JobSettings` for all URLs; there is no per-file engine/language/diarization/translation/export override in the UI, model or queue API (`enqueue(files:settings:recursive:)`). `QueueTests` cover only batch-wide settings.
4. **FILE-AC-16 "copy into library": not implemented.** Jobs always create referenced assets with a bookmark (`PersistentJobQueue+Run.swift:~150-160`); no UI option and no code path creates an owned copy for file jobs (only the meeting finalizer sets `isOwnedByLibrary`). The bookmark half is implemented.
5. **IGN-AC-05 re-derive and manual flags: engine support only.** `IgnoreFilter.FlagMode.rederive(preserving:)` exists and is unit-tested, but nothing in production uses it (`rg "rederive"` outside tests finds only the definition and `PostProcessingChain`'s doc comment). Disabling or deleting a rule in Settings never re-processes existing transcripts, so already-flagged segments stay flagged. There is also no persisted "manually ignored" marker on `Segment` (only `isIgnored`), so the `preserving` set cannot even be computed; a re-derive would un-ignore segments the user ignored by hand. Needs a `manuallyIgnored` flag plus a re-derive action on rule change.
6. **Whisper fallback notice for dictation (and live) is never shown.** `AppleAwareEngineRouter` (`Transcription/AppleSpeechAssets.swift:149-166`) puts the notice in `EnginePlan.warnings`, and `App/AppEnvironment.swift:181-182` comments "with a notice". But `RoutedEngineProvider.resolve` (`Dictation/Pipeline.swift:93-104`) discards `plan.warnings` (`ResolvedDictationEngine` has no field for them), and for live the `LiveEngineSelection.warnings` set at `LiveSessionDependencies.swift:72` and `App/LanguageRuntime.swift:66` is never read (`rg "\.warnings"` in LiveCaptions/Dictation/App finds no consumer). Users silently get Whisper instead of Apple Speech; if the Whisper model is not installed dictation fails with `modelNotInstalled` and no explanation of the fallback.
7. **DesignGuardTests do not scan LiveCaptions/Dictation for the token rule.** The glass rules do scan them (`glassScanFiles`, `panelPackagesAreScanned`), but `noLiteralColoursOutsideAllowlist` uses `sourceFiles()` (Features only). `LiveCaptions/CaptionPresets.swift:154` already builds `Color(.sRGB, ...)` and `:168` uses `.black`; neither package would be caught if a view added `Color(red:)`. Extend the colour scan to the panel packages with an allowlist entry for the user-data hex decoder.
8. **No guard that network use is confined to ModelStore and Sparkle.** The only `URLSession` users are `ModelStore/Downloading.swift` (HF manifest and downloads, HTTPS plus host allow-list plus redirect check) and Sparkle (dormant unless a valid HTTPS feed and 32-byte Ed25519 key are present). That matches the privacy claim today, but nothing enforces it. Add a source guard test (or a `scripts/check-*.py` rule) failing on `URLSession`/`NWConnection`/`WKWebView` outside those places.
9. **Test gap (ID not referenced in any test file, behaviour not verified here):** about 90 of 311 AC IDs from `specs/features/*.md` have no literal reference under test files, including DICT-AC-01..05,07,09..16, LIB-AC-03,06,11..15, IGN-AC-07,08,12,14, MTG-AC-10, ENG-AC-04..13,16, FR-AC-12..18, MENU-AC-03..06,10..13, PROD-AC-01..08. Many may be covered by untagged tests; a mapping pass (or tagging convention enforced by script) would show real holes. The list is reproducible with a grep over `specs/features/*.md` versus `Packages/*/Tests`.

## Minor

- `MeetingSessionController.beginRecording` (`:187-193`) builds the folder name with a default-locale `DateFormatter`; non-Gregorian calendars or other numbering systems change the folder name. Use `en_US_POSIX`.
- `MeetingSessionController.beginRecording` failure paths leave the remote health-listener `Task` (`state.helpers`) uncancelled when `recorder.start` fails (`:219-225`); it ends only when the stream ends.
- `RecordingRecovery.recover` loads every meeting per directory (`meetings()` inside the loop) and swallows save errors with `try?` (B7).
- `PersistentJobQueue.commit` logs persistence failures but still publishes the new state (`:233-241`); a failed `.completed` write is lost, so after a relaunch the job reads as `.running` and is re-run. Acceptable by design, but note the transcript was already saved (re-run would duplicate work, not data).
- `remove(_:)` of a batch member counts the job as "cancelled" in the batch summary and can fire a batch notification at removal time.
- `Playback.swift:304-308` calls `startAccessingSecurityScopedResource()` and never balances it.
- `AppleSpeechEngine`/`AVAudioConverter`-style force unwraps (`baseAddress!`) in `AVFileDecoder.swift:176`, `CaptureSession.swift:238`, `AppleSpeechEngine.swift:270` are all preceded by emptiness guards; `as!` in `HUDPanel.swift:49` and `SystemInsertion.swift:83` follow `CFGetTypeID` checks. No `try!` in non-test sources. `ExportService.swift:36,41` and `MeetingRuntime.swift:60` unwraps are guarded by the preceding nil/empty checks.
- `Downloading.swift:242` stages downloads in `NSTemporaryDirectory()` (`earmark-dl-<uuid>`); failures after the move are not cleaned up, and a large model temporarily needs space on the system volume rather than next to the destination. Not a privacy issue.
- `CGEventTapHotkeySource` hands `Unmanaged.passUnretained(self)` to the tap callback and has no `deinit { stop() }`; safe today because the sources live for the app's lifetime inside `GlobalHotkeyService`, a use-after-free if one is ever released without `stop()`.
- `SystemAccessibilityInserter.insert` makes synchronous AX IPC calls on the dictation actor; an unresponsive target app can block it for the AX timeout (the caret locator sets a 0.2 s timeout, the inserter does not).
- NLLB first-load uses a fixed 30 s ready timeout (`NLLB.swift:~180`) and each request 120 s; cold start of a 600M model from a slow volume could trip it and the retry loop restarts the load.
- Logging: no transcript text, dictation text or clipboard content is logged (all `log.*` call sites in non-test sources checked). Several error logs interpolate `String(describing: error)` with `privacy: .public`; engine/worker error strings and file names could appear there. Consider `.private` for error descriptions that can embed paths.
- Notifications use transcript titles or input file names as body text (`SystemJobNotifier.swift:13-20`), which appear on the lock screen. Titles derived from file names are normally harmless; worth a setting for sensitive users.
- No `applicationShouldTerminate` hook: quitting mid-recording or mid-job relies entirely on crash recovery (up to about 2 s of audio lost, job resumed from checkpoint at next launch). Works as designed but a graceful stop on quit would be better UX.
- `Dictation` depends on `Features` in `scripts/check-dependencies.py`'s approved graph (a low-level feature package depending on the UI layer); worth revisiting.
- Speculative, not verified: `AudioDeviceProvider.changes()` drops the `HAL.Listener`s (calling `AudioObjectRemovePropertyListenerBlock` in `deinit`) while holding the state `Mutex`, and `broadcast()` takes the same lock on the listener queue. If Core Audio waits for in-flight callbacks when removing a listener this could deadlock; unverified.

## Looks solid

- Jobs queue removal: `remove(_:)` reserves the id in `removing`, cancels and joins running work, persists the soft delete first, and only then clears `store` and publishes `.removed`; a storage error leaves a retryable row. Scheduling has no suspension point between the capacity check and `running[id]` registration. `insert` persists before publishing; cancellation/pause intents are applied by the run loop with the last checkpoint; the "last cancellation point" before `replaceSegments` is correctly placed.
- Checkpoint resume: segments are upserted before the checkpoint is saved, and `trimToCheckpoint` removes orphaned segments after a crash (FILE-AC-08).
- `RingBuffer` and `AudioRenderSink`: textbook SPSC with correct acquire/release ordering, no allocation or locks on the real-time path; `CaptureSession` restart/stop interleavings are guarded by `restarting`/`stopped` checks.
- Meeting recorder core: gap-free per-track timeline, flush and manifest refresh every 2 s, halt-on-low-disk keeps files closed and the recording stoppable, recovery repairs CAF headers and retries a failed mix; video failure never stops audio.
- NLLB worker: serial JSON-lines protocol with request-id check, watchdog and cancellation both terminate the helper, `stopWorker()` on every error then lazy restart via the retained model folder; the native helper bounds batch size and text length.
- Privacy: model downloads are the only first-party network path, allow-listed (`huggingface.co`, `hf.co`, HTTPS only, redirects re-checked); WhisperKit and the pyannote loader are created with `download: false`; Sparkle is dormant unless an HTTPS feed and a valid 32-byte Ed25519 key are baked in, and `SUEnableAutomaticChecks`/`SUAutomaticallyUpdate` are off by default, with no profile reporting. No telemetry, analytics or crash-reporter SDKs. Dictation pastes use transient/concealed pasteboard types and restore only if the change count is unchanged.
- Entitlements: only `device.audio-input` on a hardened-runtime, non-sandboxed app; usage strings present for microphone and system audio capture; `sign-bundle.py` signs inside-out, forces the app entitlements only on the outer bundle, rejects `get-task-allow` and requires a Developer ID identity for distribution.
- TCC handling: just-in-time requests only (`request` prompts only when `notDetermined`), denied never throws, silent-denial detection for process taps, live detection of Accessibility grant, Screen Recording requested only when video is first started.
- Focus: caption overlay and dictation HUD are non-activating panels that cannot become key; `activate()` calls are tied to explicit user actions (menu items, onboarding, accessibility sheet).
- Forced unwraps and casts in sources are all guarded; the new Swift 6 concurrency boundaries are mostly actor- or lock-based with comments stating the invariant.
