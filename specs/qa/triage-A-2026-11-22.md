## 1. Microphone says "needed" although Settings shows it enabled

### Evidence (strong)
- Installed app: `codesign -dv` reports `Signature=adhoc`, designated requirement `cdhash H"f879d9bb..."`, no hardened runtime, entitlement `device.audio-input` present, `NSMicrophoneUsageDescription` present (so the prompt can appear).
- tccd log (21:49 and 21:56 today): `Failed to match existing code requirement for subject lk.dumindu.earmark.Earmark and service kTCCServiceMicrophone`, and the stored requirement printed is `identifier "lk.dumindu.earmark.Earmark" and anchor apple generic and certificate leaf[subject.CN] = "Apple Development: ... (6LBYDXKPSF)"`.
  So the TCC row was granted to an Apple Development signed build (Xcode/DerivedData; there are 7 DerivedData Earmark builds). The /Applications copy is ad-hoc signed, so its identity is a cdhash that changes every build. System Settings still shows the old row's toggle, but TCC no longer treats this binary as that client. Toggling the switch edits the old row and cannot help.
- App defaults (`lk.dumindu.earmark.Earmark`): `permissions.requested.microphone = 1`. That flag is the stale memory described next.

### Root causes in code
1. `Packages/Permissions/Sources/Permissions/PermissionsService.swift:121-129` `resolve()` maps raw `.notDetermined` to `.denied` whenever `memory.hasRequested(kind)` is true (line 127). That heuristic exists for Accessibility/Screen Recording, which cannot distinguish "never asked" from "denied". Microphone has an exact API (`SystemPermissionProbe.swift:15-22`, `AVCaptureDevice.authorizationStatus(for: .audio)`), so the heuristic is wrong for it: after any identity change/TCC reset the app reports Denied forever.
2. `PermissionsService.swift:38-42` `request()` only prompts when `resolve()` is `.notDetermined`. With the poisoned memory, the status is `.denied`, so `performRequest` (`AVCaptureDevice.requestAccess`, `SystemPermissionProbe.swift:43-44`) is never called again. Same gate in `MicrophoneSource.swift:121-123` (`ensurePermission`: request only when `.notDetermined`), so dictation, live, mic test and meeting capture all throw `permissionDenied(.microphone)` without prompting. UI texts: dictation HUD `DictationController.swift:376` "Earmark needs microphone permission for dictation.", menu bar `MenuBarModel.swift:226`, mic test `AudioMeetingsModels.swift:97`.
3. `PermissionRow.swift:95` offers the request button only when status is `.notDetermined`; a `.denied` row shows only "Open System Settings" (`PermissionRow.swift:112-115`). So there is no in-app way to recover.
4. Staleness: `PermissionsService.refresh()/startPolling()` (lines 73-90) are never called by the app; the Settings pane re-reads on `didBecomeActive` (`PreferenceViews.swift:581-583`) which is fine, but Onboarding (`OnboardingModel.swift:18-28`) and other consumers do not. Minor, not the cause here.
5. The probe is not wrong in API choice (`AVCaptureDevice` is the correct, non-prompting query; `AVAudioApplication.recordPermission` returns the same TCC answer). No need to switch.

### Fix
A. Service (core): for `.microphone` and `.notifications` (both have exact OS states) ignore `memory.hasRequested`; add a `PermissionKind` capability, e.g. `private var osDistinguishesDenial: Set<PermissionKind> = [.microphone, .notifications]`. `resolve()` returns `.notDetermined` as is for those. Then `request(.microphone)` runs `requestAccess` when the OS says not determined.
B. Self-heal: if the OS says `.denied` and Earmark's identity changed since the last grant, show a distinct recovery note. Persist the code-signing designated requirement or cdhash (`SecCodeCopySelf` + `SecCodeCopyDesignatedRequirement`) next to `permissions.requested.*` and, on mismatch, clear the memory flags. Recovery text: "Earmark was updated and macOS no longer recognises the earlier permission. Click Reset and Allow." Offer a "Reset and Allow" button that runs `/usr/bin/tccutil reset Microphone <bundle id>` (permitted without admin for the user's own TCC rows) and then calls `request`.
C. UI: `PermissionRowState.action`:
   - `.notDetermined` -> button "Allow..." (calls `request`, which shows the system prompt).
   - `.denied` -> primary "Open System Settings" (existing link) plus a secondary "Check again" button that calls `status()`.
   - `.granted` -> none.
   Add `PermissionRowAction.recheck` for `.denied`. Add `NSApplication.didBecomeActiveNotification` -> `permissions.refresh()` once at the app level (AppEnvironment) so every consumer (menu bar, onboarding, dictation) sees toggles made in Settings, and the `changes()` stream drives the UI.
D. Dev/QA workaround right now: `tccutil reset Microphone lk.dumindu.earmark.Earmark; defaults delete lk.dumindu.earmark.Earmark permissions.requested.microphone`, relaunch from /Applications, click Allow. Longer term, sign the QA build with a stable identity (Apple Development cert or the project's self-signed cert used by `scripts/sign-bundle.py`) instead of ad-hoc so TCC grants survive rebuilds. Ad-hoc installs lose every TCC grant on each new build.

### Tests (Packages/Permissions/Tests/PermissionsTests/PermissionsServiceTests.swift, FakeProbe + InMemoryPermissionMemory)
- `microphoneNotDeterminedIsNotDeniedEvenIfRequestedBefore`: memory.markRequested(.microphone), probe raw `.notDetermined` => `status == .notDetermined`.
- `microphoneRequestPromptsAfterStaleMemory`: same setup, `request()` => probe.requested == [.microphone], result granted when `onRequest(.microphone, becomes: .granted)`.
- `accessibilityHeuristicUnchanged`: existing `undistinguishableDenialBecomesDeniedAfterRequest` keeps passing.
- `identityChangeClearsMemory`: memory stores fingerprint A, service constructed with fingerprint B => `hasRequested` false afterwards.
- Feature tests (`PermissionRowState`): `.denied` offers `.recheck`; `.notDetermined` offers `.request`; model `refresh` on activation updates statuses (inject a service whose status changes between calls).
- Manual: reset TCC, launch, Settings > Privacy > Allow shows the system dialog; Deny, row shows Denied with Open System Settings; enable in Settings, return to Earmark, row flips to Allowed without relaunch.

## 2. Zoom / Teams meeting never produces a prompt

### Wiring (verified to be in place)
- `App/AppEnvironment.swift:199-200` creates `SystemMeetingPrompter` and `install()`s categories; `:223` builds `MeetingRuntimeFactory.make`; `:91-105` `startMeetings` runs recovery and then `await meetings.detector.start()`.
- `ShellModel.startBackgroundWork()` (`ShellModel.swift:90`) starts `MeetingsModel.run()` which subscribes to `detector.events()` (`MeetingsModel.swift:217-218`) and handles `.started` (`:261-275`): default policy `askFirst` (`MeetingsSettingsModel` and `MeetingPolicy.init`, `MeetingsJobsExport.swift:39`) -> `MeetingPromptPolicy.decide` -> `.prompt` -> `SystemMeetingPrompter.present` (`SystemMeetingPrompter.swift:36-46`), which requests notification authorization lazily if not determined and posts a notification.
- User confirmed notifications permission is fine. The user's database has 0 meetings, and no `meeting started` log lines were found in the last 12 h, i.e. the detector has never fired on this machine.

### Why it does not fire for a real Zoom call (ranked)
1. Start condition is too strict. `Packages/Meetings/Sources/Meetings/MeetingDetector.swift:131-134` `isStrong` needs `micInput && audioOutput` on the app's own audio processes continuously for 3 s (`startDebounce`, line ~50). Real calls fail this very often: join muted (Zoom releases the input stream while muted, the code's own comment at `MeetingDetector.swift:30-33` admits it), listen-only/webinar, or the first seconds before anyone speaks. The `.candidate` phase also resets to idle on the first sample where either flag is off (`:149-153`) and nothing re-arms it until another Core Audio change event arrives. Fix below.
2. Per-process IO flags are the only signal. `CoreAudioMeetingProbe.snapshot` (`CoreAudioMeetingProbe.swift:48-67`) reads `kAudioProcessPropertyIsRunningInput/Output` for audio process objects whose bundle ID has the prefix `us.zoom.` or `com.microsoft.teams`. No other corroboration is used: no window titles (those need Screen Recording; the code deliberately avoids it, `MeetingPolicyEngine.swift` comment), no `CptHost`/`caphost` helper signal, no CMIO camera signal, no `deviceMicInUse` fallback (`requireDeviceCorroboration` defaults to false and is only a gate, not a trigger).
3. Teams (UNVERIFIED). The prefix `com.microsoft.teams` matches `com.microsoft.teams2` (new Teams, executable `MSTeams`), classic `com.microsoft.teams`, and helpers such as `com.microsoft.teams2.modulehost`. New Teams hosts call audio in a WebView2/WebKit-based helper; if that process reports a different bundle ID (for example `com.apple.WebKit.WebContent` or an Edge/WebView2 helper) the prefix will never match and the call is invisible. `isAppRunning` also requires an `NSWorkspace` running app with the prefix. `MeetingApp.bundleIDs` (`MeetingsJobsExport.swift:8-11`) lists only `teams2`, which is inconsistent with `MeetingAppSignature.defaults` (harmless but should be unified). The research note admitted only Zoom's main ID was confirmed.
4. Capture side bundle-ID selection (`MeetingRuntime.swift:118-126`) picks the first running non-helper app matching the prefix; for Teams that could be a different `com.microsoft.teams*` process than the audio owner. Fine for Zoom.
5. Detector listener coverage: process list and per-process listeners are attached in `AudioListenerHub.attach` on first `changes()` stream (`CoreAudioMeetingProbe.swift:~150`); if `start()` runs before Zoom exists, the relist listener picks up new process objects. This looks correct but is untested against a real call.
6. Any diagnostic? None. `ProbeMeetingDetector` logs only start/end (`MeetingDetector.swift` `log.info`); nothing logs the raw snapshot, so a failed detection cannot be debugged. The "Meetings" screen has no "Detector status" line.

### Proposed fixes
- Signals: treat a meeting as started when `isAppRunning && audioOutput` has been true for >= 5 s AND (`micInput` OR `deviceMicInUse` OR a Zoom call helper process is running (`us.zoom.CptHost`/`caphost`, spawned only in meetings; UNVERIFIED) OR output has been continuously active for >= 15 s). Keep the strict `micInput && audioOutput` as the fast path (3 s). Do not reset a candidate on a single weak sample; require 2 consecutive weak samples across the grace period.
- Teams: add explicit helper bundle IDs after observing a live call (see diagnostics), and add `com.microsoft.teams2` and `com.microsoft.teams` to `MeetingApp.bundleIDs`.
- Diagnostics (needed to close UNVERIFIED items): on every `evaluate`, log at `.debug`/`.info` the snapshot (`app running, mic, out, deviceMic`) and, behind a debug flag or the Meetings screen "Detection details" disclosure, a list of all audio process objects with `IsRunningInput/Output` and their bundle ID (`CoreAudioReads.processObjects()`), so a Teams call shows which process owns the audio.
- UI fallback: Meetings screen and menu bar already have manual "Capture a meeting"; also add "Zoom/Teams is running but no call detected - Start now" chip when the app is running with output active.
- Prompt reliability: `SystemMeetingPrompter.present` silently returns when notifications are not authorized (`authorized()` returns false; no inline fallback is shown despite the class comment saying "the inline banner in Meetings is the fallback"). Verify the banner (`MeetingsModel.promptBanner`, line ~127) renders when notifications are denied.

### Tests
- `DetectorTests` (existing `FakeProbe`): `mutedJoinStartsViaOutputPlusDeviceMic` (mic false, output true, deviceMic true, 5 s) => `.started`; `weakSampleDoesNotResetCandidate`; `outputOnlyForFifteenSecondsStarts`; `callHelperProcessCounts` once the helper is verified.
- `MeetingAppSignatureTests`: matches `us.zoom.xos`, `us.zoom.CptHost`, `com.microsoft.teams2`, `com.microsoft.teams`, `com.microsoft.teams2.modulehost`; rejects `com.microsoft.Word`.
- Manual (needs real calls): start Zoom, join muted with another participant talking; expect a notification within ~5 s. Repeat with new Teams and classic Teams while the diagnostics list is visible.
- Manual precondition to avoid false negatives: Notifications allowed (System Settings), Meetings policy Ask first (default), Earmark running (menu bar item present).

## 3. Playback lifecycle (audio keeps playing; reopen starts a second player)

### Ownership today
- `TranscriptEditorModel` owns `public let playback = PlaybackModel()` (`TranscriptEditorModel.swift:106`). `loadMedia` creates a fresh `AVPlayerEngine` via `engineFactory` (default `avEngine`, `:164-170`) each time `load()` runs (`:235-241`).
- `TranscriptEditorView.init` creates the model in `@State` (`TranscriptEditorView.swift:42-46`), hosted by `ShellView.swift:122-124` (`TranscriptEditorView(...).id(id)`).
- Navigating away: `ShellModel.select` sets `openedTranscript = nil` (`ShellModel.swift:96-100`); the editor view disappears. `.onDisappear` (`TranscriptEditorView.swift:80-84`) only acknowledges reconciliation, closes the detached window and flushes edits. It never pauses or releases the player. `AVPlayerEngine` has no `stop()`/teardown API (`Playback.swift:195-290`); its `isolated deinit` only removes the time observer.
- The transport bar and keyboard shortcuts exist only inside the editor (`PlayerViews.swift` `TransportBar`; `PlaybackKeyboardCapture` is installed by the editor view and the detached window). Once the editor is gone there is no UI to stop playback.
- The user's second symptom (reopened transcript starts from 0 while the old one keeps playing) proves the old engine/model is still alive after the view is dismissed (a retain is keeping the `AVPlayer` alive; candidates: the model captured by the `Task { await model.flush() }`, the AVPlayerView representable, the detached `PlayerWindowController` holding the model strongly, UndoManager registrations). Do not rely on deallocation to stop audio; explicit stop is required regardless of what retains it. Confirm the leak with the Xcode memory graph or a temporary `deinit` log in `TranscriptEditorModel`.
- Opening the same transcript from Queue/Library/Home calls `openTranscript(id)` (`ShellModel.swift:124-127`) which builds a new editor and model (`.id(id)`), so a new player is always created and position is not restored.

### Proposal: a single shared playback controller
- New `@MainActor @Observable final class PlaybackCenter` in `FeatureSupport` (or `FeatureEditor`), created once in `AppServices`/`ShellModel`. Holds `session: PlaybackSession?` where a session is `{transcriptID, title, PlaybackModel, engine, mediaURL}`.
- `func session(for id: TranscriptID, url: URL, factory:) async -> PlaybackSession`: if `session?.transcriptID == id` return it (resume: same engine, same position, same speed); otherwise `stop()` the current session (pause, `onTick/onPlayingChanged = nil`, `player.replaceCurrentItem(with: nil)`, remove observer) and create the new one. Exactly one engine exists at any time.
- `TranscriptEditorModel` receives its `PlaybackModel` from the center (inject, replacing the `let playback = PlaybackModel()` at line 106); `loadMedia` calls the center instead of `engineFactory` (keep the factory injectable for tests). The model keeps calling `setTimeline` on its own segments; on leaving the editor it calls `playback.detachTimeline()` so karaoke highlight does not reference a dead model.
- Navigation policy (pick one for sign-off; recommend A):
  A. Persistent mini-player: `ShellView` shows a compact bar (title, play/pause, +-15 s, scrubber, speed, close X) in the bottom safe-area/sidebar footer whenever `center.session != nil` and the editor is not showing that transcript. Click title -> `openTranscript(session.transcriptID)` (resumes, no new player). Close X -> `center.stop()`. Space toggles when no text field has focus (reuse `PlaybackKeyboardCapture` at shell level).
  B. Pause on navigation: simpler; `ShellModel.select/openTranscript` call `center.pause()` unless the target is the same transcript.
- Lifecycle hooks that must call `center.stop()`: transcript deleted/trashed, media asset relinked or missing, library moved, app quit (`applicationWillTerminate`), starting live capture/dictation/meeting capture (to avoid feedback into the mic; at least pause), and the detached window closing while not docked.
- Resume across launches (optional): persist `lastPosition` per transcript in settings and seek on first attach.

### Tests (FeatureEditorTests/FeatureShellTests with the existing scripted fake `PlayerControlling`)
- `openingSecondTranscriptStopsFirst`: session A playing, open B => fake A `pause` count 1, `releaseCount` 1, only one live engine.
- `reopeningSameTranscriptReusesSessionAndPosition`: play A to 12.0 s, navigate Home, reopen A => `session(for:)` returns the same engine object, `currentTime == 12.0`, `factory` called once.
- `navigationPausesOrShowsMiniPlayer` per chosen policy (`ShellModel.select` while playing).
- `closingMiniPlayerStopsEngine` and `deletingTranscriptStopsPlayback`.
- Leak test: create editor model + attach fake engine, drop references, `weak` model is nil (guards the retain bug).
- UI test: play in editor, click Home, mini-player visible with Pause; click it, same time, one `AVPlayer` (assert through the playback accessibility value).

### Similar lifecycle issues found
- Live capture (`LiveSessionOrchestrator`) and meeting capture intentionally continue across screens; indicator exists (`ShellModel.recordingSection`, menu bar). Acceptable but make sure a visible stop exists from every screen (menu bar yes).
- Mic test: stops on pane `onDisappear` (`PreferenceViews.swift:121`), good. But the Settings window closing or the app quitting while a test runs relies on `onDisappear`; add `stopMicrophoneTest` on window close/terminate.
- Caption overlay test caption: hidden on `onDisappear` (`PreferenceViews.swift:337`). OK.
- Detached player window: closed in editor `.onDisappear`, but its title is static (`PlayerViews.swift:244`), so after reopening nothing indicates which transcript it belongs to; goes away once the center owns the session.
- Playing media while starting dictation/live/meeting capture is not guarded (feedback risk). Pause playback on capture start.
- `TranscriptEditorView.init` builds a throwaway `TranscriptEditorModel`/`FindReplaceModel`/`EditorExportModel` on every parent body re-evaluation (State only keeps the first). Cheap but wasteful and could hide leaks; construct lazily in `.task` or via `@State` with a factory.

## 4. "Couldn't get segmentation to work"

### What it means in the product
The spec feature is Speaker Diarization (`specs/features/04-diarization.md`, DIA-AC-*), shown to users as "Identify speakers" and speaker chips/labels. Other related meanings: segment split/merge in the editor (EDIT, `SegmentOps.swift`, `TranscriptEditorModel.swift:~470-490`), which work on existing segments and are unrelated to diarization; and VAD/utterance chunking used internally. The user tested with a multi-speaker video ("NVIDIA MultiTalker ASR Demo") so they mean speaker identification.

### Root causes (confirmed)
1. Off by default and hidden. `BatchSettingsModel.swift:66` `public var diarize = false`. The batch sheet (`BatchSettingsSheet.swift:24`, "Options > Identify speakers") appears only for files added through Queue (`QueueView.swift:29-38`). Files dropped on the window or chosen via Home "Transcribe" go through `ShellModel.enqueue` (`ShellModel.swift:148-157`) with `FileJobSettings.load` defaults, which contain no diarization setting (`FileJobSettings.swift` has no `diarize`; no Settings pane default either). The user's database confirms it: all 7 `transcribeFile` jobs, including the multi-speaker demo, have `settings.diarize = false`, so they ran no diarization and show no speakers.
2. Models are not installed on this machine. `~/Library/Application Support/Earmark/Models/state.json` lists only whisperkit small, whisperkit large-v3 and NLLB; no `fluidaudio/diarization-community-1` or `fluidaudio/ls-eend-ami`. File jobs would download Community-1 on demand (`PersistentJobQueue+Run.swift:278` `ensureModel`, catalog `Catalog.swift:68-72`), but:
   - the live path has no download step: `LiveSessionOrchestrator.swift:221-232` runs `diarizer.stream` and on a missing model only logs `diarization stopped` ("best effort"), so live captions silently lack speaker labels;
   - meeting finalization (`MeetingFinalizer.swift:262-272`) degrades with a `diarizationFailed` warning, and `MeetingFinalizer.makeJob` (`:157`) never ensures the model;
   - a diarization download/inference error in a file job is not caught (`PersistentJobQueue+Run.swift:65` `try await diarize(...)`), so the whole job fails after transcription, contradicting DIA-AC-16 ("continue without labels, offer retry").
3. No speaker count UI. `JobSettings.diarization` (`["exact":n]` or `["min":a,"max":b]`, `PersistentJobQueue+Run.swift:288-294`) has no UI anywhere (DIA-AC-02 unwired); auto only.
4. No "identify speakers on an existing transcript" action. Searching `Features/Sources` finds no re-diarize/retry entry (DIA-AC-16 retry is unwired). A user who forgot the toggle must re-queue the file.
5. Live: `LiveModel.swift:245` `diarize: source != .mic`; mic-only live never diarizes and there is no toggle. In mic+system with lanes the mic lane is labelled "You" (`App/LiveSupport.swift:43-44`) and only the system lane is diarized (max 4, LS-EEND, "More speakers" beyond that).
6. Meetings: the user's DB has 0 meetings, so the meeting path has never run here.

### How multi-speaker works end to end (for the test procedure)
- File: Queue (or Home drop) -> batch sheet -> Options -> toggle "Identify speakers" (per-file override picker in "Per-file" section, `batch.file.N.diarize`) -> Add. Job pipeline: transcribe -> (if diarize) ensure Community-1 model download (job note "Downloading Diarization Community-1...") -> note "Identifying speakers" -> `FluidAudioDiarizer.diarize` -> `assignSpeakers` (`PersistentJobQueue+Run.swift:300-312`) gives "Speaker 1..N" with palette colours and assigns each segment by maximum overlap -> saved. Open the transcript: speaker chips/labels in the list (View option `showSpeakers`, default true, `ViewOptions.swift:31`), "Speakers" toolbar button and inspector list (rename/merge/colour/reassign, voice profiles).
- Live: Live screen with source System/App/Mic+System (not Mic only) -> chips with provisional labels within ~1.5 s (needs LS-EEND installed; not auto-downloaded).
- Meetings: dual-track; mic = "You", remote track diarized offline at finalization, plus live-to-offline reconciliation banner.

### Fixes
- Default: add `FileJobSettings.diarize` from a Settings > General/Transcription toggle "Identify speakers in new transcripts" (default on when the model is installed or downloadable; at minimum surface the toggle on the Home drop path with a first-run prompt). Make `ShellModel.enqueue` honour it.
- Preflight: when the user enables "Identify speakers" and the model is absent, show size and download inline (same pattern as the ASR model picker in the batch sheet), and add Community-1 and LS-EEND to onboarding/Models "recommended" lists. For live, call `models.ensureAvailable(lseendAMI)` before start or show a notice "Speaker labels need the Live speaker model - Download".
- Robustness: wrap `diarize(...)` in `do/catch`; on failure set a job note/warning and complete the transcript without speakers (DIA-AC-16), and add an editor banner "Speakers could not be identified. Retry" that enqueues a diarize-only job on the existing transcript (reuse `MeetingFinalizer` diarization step or `assignSpeakers`).
- Speaker count: add Auto / Exact / Range controls under "Identify speakers" (maps to `JobSettings.diarization`).

### Tests
- `JobQueueTests`: `diarizeEnabledAssignsSpeakersWithMockDiarizer` (exists likely; extend), `diarizerFailureCompletesWithoutSpeakers`, `diarizationOptionsMapsExactAndRange`, `fileJobSettingsLoadReadsDiarizeDefault`, `enqueueFromDropUsesDiarizeDefault`.
- `BatchSettingsModelTests`: toggling model-missing state shows download prompt; `jobSettings.diarization` reflects Exact/Range.
- `LiveSessionTests`: missing LS-EEND model => notice surfaced (not only a log).
- Manual script: (1) ensure models: Settings > Models, install Diarization Community-1 (and LS-EEND for live). (2) Queue > Add the two-speaker sample (e.g. `~/Downloads/NVIDIA MultiTalker ASR Demo....mp4`), enable Identify speakers, Add. (3) Wait for "Identifying speakers" note and completion. (4) Open transcript: expect >= 2 distinct speaker chips; rename Speaker 1, merge two, reassign a word range, export TXT/DOCX and check names. (5) Repeat with Home drop and confirm the same result once the default is wired. (6) Live: choose System audio, play the sample, expect chips within ~2 s; choose Mic only and confirm no chips (by design). (7) Delete the diarization model and rerun: job must still complete with a visible warning (after the DIA-AC-16 fix).
