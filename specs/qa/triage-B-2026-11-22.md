## (a) DMG installer window clipped
Files: scripts/dmg/settings.py (window_rect), scripts/dmg/make-background.swift (width/height 660x420, footer text at top 369/397), scripts/make-dmg.sh (manifest hardcodes windowSize [660,420]), scripts/dmg/test_verification.py (may assert size).

Root cause: `window_rect = ((160,120),(660,420))` is the Finder window FRAME, which includes the ~28 pt title bar even with toolbar/status/path bars hidden. Content area is therefore ~660x392, so the bottom 28 pt of the 660x420 background (footer lines at y=369 and 397 incl. "LOCAL PREVIEW") are cut off. icon_locations are in content coordinates (unaffected by the title bar).

Fix:
1. settings.py: `window_rect = ((160,120),(660,420+28))` = (660,448). Keep show_toolbar/pathbar/status_bar/sidebar False. Put the 28 in a named constant `TITLEBAR = 28`.
2. make-background.swift: also pull the footer inward for safety (note at top 369 -> ~352, LOCAL PREVIEW / Open Anyway line 397 -> ~384, leaving >=28 pt bottom margin), so a 1-2 pt chrome variance on other macOS builds never clips text.
3. Icon padding: icon_size 128 with 80 grid and icons at x=170/490 is tight against label text; use icon_size 112, text_size 13, icon_locations y=190 (centered in the visible area between header block ending ~y=100 and footer ~y=340), x 180/480. Make background arrow/drop target art match the new coordinates.
4. make-dmg.sh manifest `windowSize` -> [660,448]; update test_verification.py expectations.
5. Verify by mounting and screenshotting (Finder bounds read via AppleScript `bounds of window`).
Effort: 1-2 h incl. rebuilding and visually verifying (cannot unit test the clipping).

## (b) Toolbar cramped
Shared root causes:
- Custom `EmberButtonStyle` (DesignSystem/EditorialComponents.swift:4) is a hand-drawn Capsule with `padding(.horizontal, 16)`, `minHeight 36` (DSLayout.prominentControlHeight) and hand-set font. In a toolbar it bypasses the system glass button style, controlSize and the toolbar's own item padding/metrics, so it renders taller/denser than neighbours and has no glass/pressed/disabled behavior. Combined with `.sharedBackgroundVisibility(.hidden)` the system has no container to give it inner padding. Used at ShellView.swift:113 (PrimaryToolbarButton at :179, Home "+ Transcribe"), TranscriptEditorView.swift:162 (Export), LiveView.swift:101 (Start).
- Items put in one `ToolbarItemGroup` share a single glass capsule with no spacing control, so heterogeneous controls (Button, Menu, Stepper, segmented Picker, menu Picker) collide: QueueView.swift:102-128 has Add + Clear Finished (titleAndIcon) + Menu + Stepper in ONE group. LibraryView.swift:234-250 has segmented Layout + Sort menu Picker + Delete in one group (segmented picker inside a glass group looks nested). Live: LiveView.swift:77-107.
- `labelStyle(.titleAndIcon)` on ordinary toolbar buttons (Clear Finished, Stop, Search transcripts at ShellView.swift:88-90 with `.controlSize(.large)`) makes them wide pills with no min padding; `.controlSize(.large)` in a toolbar is non-standard (toolbar controls are regular size; large changes height only, not metrics of neighbours).
- Live pill: `StatusPill`/`RecordingIndicator` (Components.swift:153,204) are bare custom views in a ToolbarItem with 8/3.5 pt padding, no system background; looks cramped next to the glass picker. Fixed `.frame(width: 260)` segmented picker (LiveView.swift:123) in the toolbar leaves no room and clips at narrow widths (switch at layout.width<1250 helps but is arbitrary).
- DesignSystem has GlassToolbarButton (Components.swift:101) but features do not use it.

Fixes (HIG, macOS 26):
1. Replace EmberButtonStyle in toolbars with `.buttonStyle(.glassProminent)` + `.tint(DSColor.accent)`; keep the label `Label("Transcribe", systemImage:"plus")`; no explicit font/padding/frame. Remove `.sharedBackgroundVisibility(.hidden)` so the system supplies the prominent background and padding. Keep EmberButtonStyle for in-content primary actions only (add `.controlSize(.large)` there if needed).
2. Split groups by function with `ToolbarSpacer(.fixed)` between: Queue = [Add][Clear Finished] | [Actions menu] | [Stepper moved out of toolbar into the Queue header or Batch settings; steppers do not belong in toolbars]. Library = [Layout segmented] | [Sort menu] | [Delete]; wrap Layout in its own ToolbarItem; use `.pickerStyle(.menu)` or icon-only segmented labels. Live = [Source] | [status] | [Pause][Stop/Start].
3. Icon-only buttons by default (`.labelStyle(.iconOnly)` is the toolbar default); only the single primary action keeps title+icon. Drop `.controlSize(.large)` from the Search button; use `.searchable(placement: .toolbar)` everywhere instead of a fake search capsule (Library already does; Home/Queue/Live use a Button titled "Search transcripts" at ShellView.swift:87-103 that opens a popover; either make it icon-only magnifier, or use a real `.searchable` with `.searchToolbarBehavior(.minimize)`).
4. Source picker: use `Picker(...).pickerStyle(.segmented)` without fixed 260 width (let toolbar size it; use short labels "Mic", "System", "Both") or always `.menu`. Remove the 1250 pt switch.
5. Live pill: use a `Label` with `.padding(.horizontal, 8)` inside its own ToolbarItem (system gives it a glass background), or move recording state into the content header; Pause icon-only `.glass`.
6. Add DSLayout constants only if truly needed; remove `toolbarControlHeight` usage if any.
Effort: 3-5 h (touches 5 views, needs visual check at 960/1100/1400 pt widths); stepper relocation +1 h.

## (c) Translate popover (EditorPanels/TranslatePanel.swift)
Code: TranslatePanel.swift `body` (Form .grouped, `.frame(width: 380)`, ~line 128-152) and `readinessView` (~line 190). Presented via `.popover(item: $activeTool)` at TranscriptEditorView.swift:86 with `.dsEntrance()` and `presentationBackground(DSColor.contentBackground)`.
Root causes:
- Popover content has width but NO height: a grouped Form inside a popover sizes to its ideal height only when no ScrollView is involved; on macOS a grouped Form is scroll-backed, so the popover collapses to a short fixed height and clips the Translate section/progress (this is the "clipped" symptom). Needs `.fixedSize(horizontal:false, vertical:true)` or explicit `.frame(minHeight:)`/`idealHeight`, or replace Form with VStack content.
- The two Sections (View, Translate) each draw grouped-form cards with their own insets inside a popover that already has padding, so double inset (cramped, label/value squeezed in 380 pt; picker labels "Into" and long "Language (needs download)" values truncate).
- The "Translate" button: plain `Button("Translate", symbol:)` in a grouped Form renders as plain/link-like text row (no bordered/prominent style) and is `.disabled(model.isTranslating)` plus `selectedReadiness == .ready` gating; while `panel.targets` is still loading or readiness is `.needsModel` the Button is replaced, so it appears dim/low-contrast. There is no prominence: it is the primary action of the popover.
- Progress: `ProgressRow` plus a Cancel button are stacked in the same Section without spacing.
Fixes:
1. Replace root with `VStack(alignment:.leading, spacing: DSSpacing.md)` inside `.padding(DSSpacing.lg)`, `.frame(minWidth: 340, idealWidth: 360)`, `.fixedSize(horizontal:false, vertical:true)`. If keeping Form, use `.formStyle(.columns)` (compact label/control rows, no card insets).
2. "View": segmented picker full width with `.labelsHidden()` and a caption above. "Into": `Picker` menu style, `.frame(maxWidth: .infinity)`.
3. Translate button: `.buttonStyle(.borderedProminent)` (or `.glassProminent`), `.controlSize(.large)`, `.frame(maxWidth: .infinity)`, `.keyboardShortcut(.defaultAction)`; enabled whenever readiness == .ready (disable only while translating). Show Download model with the same style when needed.
4. Progress block: `ProgressView(value:)` + status text + Cancel as a trailing `.bordered` small button, in a HStack, with `.padding(.top, DSSpacing.sm)`.
5. Use `.presentationSizing(.fitted)` (macOS 15+) on the popover content.
Effort: 2 h.

## (d) Export sheet (EditorPanels.swift:213-345)
- "Save as preset" row (~line 238-246): `TextField("Save as preset", text:).textFieldStyle(.roundedBorder)` inside an HStack within a ScrollView. The oversized focus ring and the cursor jammed at the left edge come from the rounded-border field being stretched in a ScrollView/VStack with the app-wide custom paper background and no horizontal padding; the focus ring is clipped/offset because the ScrollView content has no inset (ring draws outside the scroll bounds), and a bordered field in an opaque `contentBackground` sheet loses its inner padding. Fixes: add `.padding(.horizontal, DSSpacing.xs)` to the scroll content (or `.scrollContentBackground`+`contentMargins(DSSpacing.sm)`), use `.textFieldStyle(.roundedBorder)` with `.controlSize(.regular)` and `.frame(minHeight: 28)`, `.onSubmit { save }`, `.prompt` text, and put the field+button in a labeled "Presets" Section with a header.
- Save button is the default bordered style with `.disabled(trimmed.isEmpty)`, so it looks dim whenever the field is empty (expected) and low-contrast on the solid paper background. Fix: `.buttonStyle(.bordered)` with `.controlSize(.regular)` and clearly enabled state once text exists; optionally `.borderedProminent` when enabled.
- Format grid (`formatGroup`, ~line 277-296): `LazyVGrid` with 4 flexible columns, each pill a plain-styled Text with `minHeight: DSLayout.minControlHeight (28)` and Capsule backgrounds, in an 840 pt wide sheet; documents list (~12 formats) yields 3 rows of big pills. Fix: use `GridItem(.adaptive(minimum: 64, maximum: 84), spacing: 6)`, `.controlSize(.small)`-height (22-24 pt), or replace with a segmented/menu `Picker("Format")` grouped by Documents/Subtitles; width 840 -> `.frame(minWidth: 720, idealWidth: 760)` and shrink preview pane to 240.
- Buttons: primary "Export PDF…" uses EmberButtonStyle with `.keyboardShortcut(.defaultAction)`; Cancel is default style. Replace with `.buttonStyle(.borderedProminent)` + `.tint(DSColor.accent)` and `.controlSize(.large)`; Cancel `.buttonStyle(.bordered)`. Disabled state (`export.isWorking`) should show a `ProgressView().controlSize(.small)` instead of just dimming.
- "Copy and share" Menu (~line 249): label with systemImage in a default menu style on an opaque sheet; make it `.menuStyle(.borderedButton)` `.fixedSize()` so it matches Cancel/Export height, and add `.menuIndicator(.visible)`.
- Sheet padding: `.padding(DSSpacing.xl)` plus grouped options VStack `padding(.lg)` card inside ScrollView, preview `frame(width:280,height:410)` is fixed (clips on 13" displays at 840 wide, ~ 900pt tall). Use `.frame(minHeight: 360, maxHeight: .infinity)`.
Effort: 2-3 h.
