# Triage C: language/model/speaker selection and model downloads (2026-11-22)

Read-only investigation (no code changed, no build or test run). Evidence is file:line level where stated; HuggingFace facts come from public `api/models/.../tree` and `curl -sI` HEAD requests made today. Effort: S = under 1 day, M = 1-3 days, L = 3+ days.

## 0. Headline findings

1. A batch-settings sheet (language, model, diarize, translate, per-file overrides) already exists but is reachable **only from the Queue screen**. A drop on the window or Home, and "Transcribe File...", enqueue immediately with saved defaults and never show it. The sheet also never saves what the user chose.
2. The editor can only re-transcribe **one segment** as **one language** with the **globally saved model**. No whole-transcript or selection run, no multi-language, no model choice. The speaker panel does rename/colour/merge/add and word-level reassignment, but there is **no way to give a speaker count or re-run diarization**, although the job pipeline and both diarizers already accept `DiarizationOptions`.
3. `ModelDescriptor` has no capability data beyond `languages`, `minTier`, `sizeBytes`, `kind`, `runtime`, `isExperimental`. No live, word-timestamp, speed, RAM, diarization or translation flags, and no "recommended". The same tier-to-default-model rule is hard-coded in at least three places (`DefaultEngineRouter.fileWhisper`, `PreferredModel.fileModels`, `OnboardingLanguageModel.fallbackModel`).
4. **Download bug (high):** three catalog entries point at the HF *repo root*, so the downloader fetches the whole repo: LS-EEND 2.1 GB (catalog says 50 MB), Sortformer 11.4 GB (catalog says 60 MB, includes the v2.1 weights that `Diarization/ModelResolution.swift` says must never be used), Parakeet 3.6 GB (catalog says 600 MB). Community-1 diarization pulls 129 MB (catalog 60 MB) including unused `mlpackages`, plots and alternate encoders.
5. Library "Re-transcribe" enqueues a job on the existing transcript with `diarize=false`; the job wipes all segments (`trimToCheckpoint` with no checkpoint keeps none), so **edits, ignore flags, speaker assignments and segment IDs are lost**. Whole-transcript re-transcribe must not reuse this path as is.
6. **Resume bug (high, traced from code, not reproduced):** HF `resolve/` URLs redirect to `us.aws.cdn.hf.co` URLs signed with a ~1 hour `Expires`. Resume data embeds that signed URL. After a pause or failure longer than that, resuming gets a 403, which `Transfer` turns into `URLError.badServerResponse` (not `DownloadInterruptedError`), so `perform` never deletes `.partial/<model>/resume/<hash>`; every Retry reuses the stale data and fails the same way, and the failed row offers Retry only (no Cancel), so the user is stuck.
7. The app is **not sandboxed** (entitlements: only `device.audio-input`), so no `network.client` entitlement is needed and there is no ATS issue; the Sinhala/NLLB/Apple-asset catalog entries are all valid today. Remaining download risks are listed in section 5.

## 1. Language and model choice when adding files

### What exists
- `Packages/Features/Sources/FeatureQueue/BatchSettingsModel.swift` and `BatchSettingsSheet.swift`: language kind (one / auto / several), model list filtered through `LanguageCapabilityTable` (ADR-008), inline `ensureAvailable` progress, diarize toggle, translate, auto-export, copy-into-library, per-file overrides (FILE-AC-04). Defaults load from `FileJobSettings.load` (`defaults.languageMode`, `defaults.preferredModel`).
- Entry points: `QueueModel.presentBatch(urls:)` (QueueView drop and "Add Files...").

### Gaps
- `ShellModel.handleDrop`/`enqueue` (ShellModel.swift ~140-155, used by the window drop and the "Transcribe File..." importer, `ShellView.swift:52-57`) and `HomeModel.enqueue` (HomeView drop zone, `HomeView.swift:221`) call `jobQueue.enqueue(files:settings: defaults)` directly. Three different add paths, only one with choices.
- The sheet never persists the language/model choice (`QueueModel.setConcurrency` is the only settings write in FeatureQueue), so "remember my last choice" is not implemented and the user must change Settings to change the default.
- The model picker is a plain `Picker` of display names with "(download)"; it shows no size, no experimental/non-commercial flag and no licence consent for a CC-BY-NC or SA model (consent only exists in Settings > Models `preflight`). `selectModel` downloads immediately.
- Per-file overrides do not support "several languages".

### Design
- One entry point: `ShellModel.requestAdd(urls:)` that every path (window drop, Home drop, importer, Dock/Open With) calls. It sets `batch = BatchSettingsModel(...)` on the **shell**, and `ShellView` presents `BatchSettingsSheet` for every screen (move the `.sheet(item:)` from QueueView up to ShellView; keep `QueueModel.presentBatch` delegating to it).
- Add a "quick add" preference `files.askBeforeAdding` (default **on**, key in `SettingsKey`). When off, behave as today with saved defaults. The sheet gets a "Don't ask again, use these settings" checkbox that flips it, and Settings > General exposes it.
- Layout (macOS 26 HIG sheet, one grouped Form): header "Add N files" with summary; row 1 **Language** (menu: Auto-detect, recent languages, "Several languages..." which expands chips); row 2 **Model** (menu "Automatic (Recommended: Whisper large-v3)" then compatible models; incompatible ones disabled with a reason using the shared `ModelCompatibility` from section 3); row 3 **Speakers** (Off / Auto / "Number of speakers" stepper / "Between 2 and 6") bound to `JobSettings.diarization`; Translate; Auto-export; per-file disclosure unchanged.
- Remember last choice: on submit, `FileJobSettings.save(_:to:)` writes `defaults.languageMode`, `defaults.preferredModel` (or clears for Automatic), `files.diarize`, `files.speakerCount`, plus a small MRU list `files.recentLanguages` (max 5) shown at the top of the language menu. Only write when the user edited something (reuse `hasEditedConfiguration`).
- Sensible defaults: English or the saved mode; model "Automatic"; if Sinhala is chosen and the Qwen model is not installed, show size (1.0 GB), the CC BY-SA/experimental note and a Download button before enabling "Add to Queue" (satisfies LANG-AC-10).
- Multi-file with different languages is already covered by per-file overrides; add an "Apply language to all / only selected" affordance in the per-file list (S).

### Tests
- FeaturesTests: `BatchAddRoutingTests` (all four entry points produce `batch != nil` when `askBeforeAdding`, enqueue directly when off), `FileJobSettingsSaveTests` (round trip, incompatible model cleared, MRU order), `BatchSettingsModelTests` additions for speaker-count mapping to `["exact": n]` / `["min","max"]`. XCUITest: drop a file on Home, sheet appears, choose Sinhala, queue row shows language.

## 2. Transcript (Editor): language, re-transcribe, speakers

### What exists
- Segment language: `TranscriptEditorModel.setLanguage(_:for:)` relabels only (no ASR). `retranscribe(_ id, as language:)` (`TranscriptEditorModel+Language.swift`) runs `SegmentRetranscriptionService` (`LanguageSupport.swift:12`, adapter in `App/LanguageRuntime.swift:17`) for one segment with a single language; engine is routed for that language; the user's saved `explicitModel` is used when it covers the language; old text kept as `SegmentRevision`; one undo step. Context menu "Re-transcribe As" only (`TranscriptListView.swift:290`). Adapter throws `modelNotInstalled` and the editor only shows a text hint (no download button).
- Speakers: `SpeakersPanel`/`SpeakerRow` (`EditorPanels.swift`): rename, colour, add, merge into, save voice profile; `reassignWords` (DIA-AC-11); `setSpeaker(_:for:)`; live-vs-final reconciliation banner.
- Diarization plumbing: `DiarizationOptions(.auto/.exact/.range)` (`AppCore/Diarization.swift`), honoured by `FluidAudioDiarizer` (`numSpeakers`, `maxSpeakers`) and `SpeakerKitDiarizer`; `JobSettings.diarization: [String: Int]` decoded by `PersistentJobQueue.diarizationOptions` (`["exact": n]` or `["min","max"]`). **No UI writes it** (grep: no Features reference), and no code re-diarizes an existing transcript.

### Missing
1. Transcript-level language: no control that shows/changes `transcript.languages` for the whole file or tells the user which languages were detected.
2. Multi-language selection for a re-run (`LanguageMode.multilingual`) from the editor.
3. Re-transcribe of the whole transcript or a selection (range, multi-select segments) with chosen language(s) and model, preserving user edits.
4. Model choice for a re-run (adapter reads the global `explicitModel` closure; `SegmentRetranscribing.retranscribe` takes `TranscriptionOptions.modelID` but the editor protocol does not pass it).
5. Speaker definition: expected count/range, optional names; re-run speaker labeling on an existing transcript; map result onto existing named speakers instead of creating "Speaker N" again; assign a speaker to a selection from the toolbar (only context menu/word popover today).
6. `JobKind.retranscribeSegment` exists in AppCore but nothing consumes it; there is no non-destructive job for partial or whole re-runs.

### Design

**A. New "Language and Speakers" sheet** opened from an editor toolbar button (language badge showing "English" / "English + Sinhala"), also from the context menu "Re-transcribe...". Scope picker: Selection (n segments) / Visible range / Entire transcript. Fields: Language (single, several, auto), Model (shared `ModelPickerList` with compatibility greying), "Keep edited segments" toggle (default on: segments with `isEdited`/manual flags are skipped, listed in the summary), Speakers section (below). Primary action "Re-transcribe", with a cost hint ("about 12 min on this Mac") from model speed tiers.

**B. Service API (AppCore SCR).** Extend `SegmentRetranscriptionService` with
`retranscribe(segments: [Segment], mediaURL: URL, languageMode: LanguageMode, modelID: ModelID?, progress:) -> AsyncThrowingStream<RetranscriptionEvent>`.
Implementation: group contiguous segments into ranges, run `SegmentRetranscriber` per range (it already clamps to ranges and supports a fixed language; add multilingual via `MultilingualEngine`/LID already used for live and `FileTranscriptionPipeline`), then **re-align** the new text onto the existing segment IDs when counts differ: produce replace/insert/delete in one `EditDelta` so it is a single undo step and each replaced segment keeps `speakerID` by max time overlap, ignore flag only if the new text still matches rules (re-run `IgnoreRederiver`), and writes one `SegmentRevision` per replaced segment. Do **not** reuse the destructive library job path; for entire transcript run the range path over [0, duration] so edits, bookmarks, highlights and speakers survive (bookmarks/highlights are keyed by time/segment IDs, re-point by overlap).

**C. Speaker model.** New `SpeakerHints` value type in AppCore: `count: DiarizationOptions.Count`, `names: [String]` (optional ordered names). Editor "Speakers" section in the sheet: Auto / Exactly N / Between A-B, plus a names field (comma separated, or per-row after count is chosen). New model method `TranscriptEditorModel.relabelSpeakers(hints:)`: runs offline `Diarizer` on the media (`diarize(file:options:)`), maps turns to segments with `TurnAssigner.slot`, then **maps new slots to existing speakers**: same-slot to same-voice via voice-profile embeddings where present (`VoiceProfileMatcher`), otherwise by greatest overlap with the previous labeling so renames/colours survive; unmatched new speakers take the next provided name, else "Speaker N". Undo is one `EditDelta` (speakers + segment assignments). Requires the Community-1 model (download with progress through the same inline flow). Expose the same hints in `BatchSettingsModel` (section 1) and in Library "Re-transcribe".

**D. Speaker panel additions** (EDIT-AC-08 follow-up): "Number of speakers" row (detected count, "Re-detect with 2 / 3 / ..."), per-speaker "Assign selected segments", "Split speaker" is out of scope.

**E. Errors/UX.** Missing model: show size, licence and a Download button inline in the sheet (reuse the batch inline-progress component, extract `InlineModelDownload` into FeatureSupport). Cancel supported; progress via `TranscriptEditorModel.retranscribing` extended to a count/fraction.

### AppCore changes (SCR-011, additive, versioned decode)
- `SpeakerHints`; `RetranscriptionScope`/`RetranscriptionRequest` (ids, languageMode, modelID, keepEdited); protocol method above with a default implementation that loops the single-segment call so existing mocks compile.
- `Segment` has no "user edited" flag (fields: id, start, end, text, speakerID, languageCode, languageConfidence, confidence, noSpeechProbability, isIgnored, ignoreFlagIsManual, words, translations). "Keep edited segments" therefore needs an SCR-011 addition such as `Segment.isUserEdited` (additive, `decodeIfPresent`, following the `ignoreFlagIsManual` precedent from SCR-010), set by text edits and speaker/language corrections.

### Tests
- Transcription: `SegmentRetranscriberTests` for multi-range, multilingual set, explicit model passthrough, empty-speech result. Features: `EditorRetranscribeRangeTests` (speaker preserved, undo restores exactly, revisions recorded, kept-edited skipped), `SpeakerRelabelTests` (hint maps to `DiarizationOptions`, slot-to-existing-speaker mapping, names applied, voice-profile match wins, undo). Jobs: `diarizationOptions` already tested; add a Library re-transcribe regression test that edits/speakers are not lost (will fail today by design, fix with section 6 item).

### AppCore capability model (SCR-011)
Add to `ModelDescriptor` (all `decodeIfPresent` with conservative defaults, since custom models persist in `state.json`):
```swift
public struct ModelCapabilities: Codable, Hashable, Sendable {
    public var live: Bool              // usable for streaming captions/dictation
    public var file: Bool
    public var wordTimestamps: Bool
    public var autoDetectLanguage: Bool

```

Fill values for built-in entries from measured data already in notes (Whisper large "about 13x real time on M3 Pro", turbo first load about 115 s, Qwen "about 2.3 GB peak", CER figures). Unmeasured values stay `nil` and render as "Not measured" (do not invent numbers).

### Download manager review
Good: allow-listed hosts only, redirect target re-checked, safe relative paths, per-file resume data, atomic move into place, SHA-256 from LFS oids, paused state persisted, tokenizer fetched as a separate recoverable step, failure message surfaced, checksum mismatch discards partials.

Risks, in order of user impact:
1. **Wrong sizes and whole-repo downloads** (above): progress totals use manifest bytes, so a user sees "2.1 GB" for a "50 MB" model, and `preflight` disk check uses the catalog size (60 MB vs 11.4 GB).
2. **No consent or licence gate on inline downloads.** Settings > Models runs `preflight` (non-commercial, tier, disk); `BatchSettingsModel.selectModel`, `OnboardingLanguageModel`, `HomeModel` (`ensureDefaultModel`, automatic) and the job queue (`ensureModel`, automatic for any routed model, FILE-AC-05) call `ensureAvailable` with no `preflight`, so the 1 GB Sinhala CC BY-SA model can start without the licence/size confirmation LANG-AC-10 expects. Not verified: onboarding (`manual.md` says it has a consent step) and `TranslatePanel.downloadModel` (user presses a button after `needsModel`; whether it shows size and licence was not checked). Route the confirmed gaps (batch sheet, queue auto-download, Home) through a shared `ModelDownloadGate`; audit the other two first.
3. **Unhandled network conditions.** `URLSession(configuration: .default)` per file with no `waitsForConnectivity`, no retry/backoff and no distinct offline message (user sees `URLError.localizedDescription`); HF API 429/5xx on the manifest call is mapped to `badServerResponse` with no retry; tree API is called without pagination handling; checked today: the largest listing (Sortformer, 424 files) returns no `Link` header, so it is complete now, but a bigger repo would silently truncate a bigger repo and then fail checksum/size or load a partial model. Treat "fewer files than expected" as an error by recording an expected file count/`sizeBytes` per entry and verifying after download.
3b. **Expired signed resume URLs** (see headline 6): on any non-2xx response or `cannotResume` error, delete the resume file and retry once from a fresh `resolve/` URL; also add Cancel to the failed row.
4. **Resume across relaunch.** Resume data lives per file under `.partial`, but a force-quit mid-file leaves `.partial` without `persisted.paused`, so the next run restarts the interrupted file from zero (completed files are kept by size). Acceptable, but the UI shows 0% until files are skipped; seed progress from existing sizes (`done` is already computed, call `emitProgress` once).
5. **Disk path.** Downloads land in `FileManager.temporaryDirectory`, then move into `Application Support/Earmark/Models/.partial`; on the usual single volume both moves are renames. The app builds `ModelManager` with `defaultRootDirectory` and no code relocates it (`StorageRelocation` is for the library), so no cross-volume issue today; if the models root ever becomes configurable the final `moveItem` stops being atomic. The free-space check uses the home volume and the catalog `sizeBytes`, which are wrong for the repo-root entries (risk 1).
6. **No integrity on small files and single files** (Qwen non-LFS files, MADLAD, tokenizer files): trust TLS only. Pin revision SHAs; for tokenizers pin `resolve/<commit>/` instead of `main` so upstream edits cannot break loading.
7. **Packaged-app verification gaps** (not code defects, but nobody has proved them): `scripts/verify-release.py` does not assert that `mlx-swift_Cmlx.bundle/default.metallib` ships in the release app (it exists in the Debug build at `DerivedData/.../Earmark.app/Contents/Resources/`), so a Release/DMG build that loses the bundle fails only when Sinhala transcribes; there is no test that Qwen/NLLB/WhisperKit/FluidAudio run **offline** after download (`Qwen3ASRModel.fromModelDirectory` and WhisperKit can try Hub fetches when a file is missing; `NetworkGuardTests` only guards first-party source). Add a release-checklist item: with networking blocked, transcribe Sinhala, translate si-en, diarize, Whisper file job.
8. **Apple assets:** `AppleSpeechAssetProvider` represents "Apple Speech" by the system language only; `install` polls `request.progress` every 200 ms on a detached loop and reports 0 until the request starts; there is no retry or "needs Wi-Fi" message and an install cancelled by the user surfaces as a generic error.
