# Native translation checkpoint quality protocol

This protocol is fixed before scoring the restored checkpoints. It complements tokenizer/native parity; it is not a claim that a model translates every sentence correctly.

- Dataset: original FLORES-200 devtest, NLLB Team (2022), CC-BY-SA 4.0. Source: https://github.com/facebookresearch/flores/tree/main/flores200. Keep corpus text and hypotheses outside Git; retain archive/per-file digests and aggregate results. The original archive SHA-256 is `b8b0b76783024b85797e5cc75064eb83fc5288b41e9654dabc7be6ae944011f6`.
- Selection: 30 shared parallel row indices sampled without replacement with Python `random.Random(110)`, sorted before inference. No selection based on the model's outputs. The six initial OPUS directions are en↔de, en↔fr and en↔es.
- Metric: SacreBLEU 2.5.1 chrF++, word order 2, default character order 6 and beta 2. Record its complete signature. Do not introduce an implicit tokenizer download.
- Execute the actual arm64 helper, 4 CPU threads, beam 4, max output 256 tokens, no Python dependency in the app. Each pack uses its own source and target SentencePiece files and appends source EOS. Record helper and model artifact digests.
- Initial OPUS acceptance: no empty/failed results; corpus chrF++ at least 35 for each direction; no more than 2 chrF++ points below CTranslate2 4.6.0 CPU float32 inference on the same pinned converted weights, same inputs and decoding parameters. This is a small compatibility/quality floor, not a population-wide quality guarantee. Semantic cases for names, identifiers, numbers and negation are separate checks.
- Count preservation of integer tokens with two or more digits present in both source and reference as a diagnostic; do not treat localized number formatting or reference paraphrases as proof of a model failure.
- Report time separately. Results under another build or memory-heavy process cannot establish latency or hardware recommendations.
- MADLAD/NLLB multilingual scoring is exploratory until per-direction quality acceptance is reviewed. Do not apply a Western-language threshold to low-resource directions without an appropriate reference. Native parity and language-tag execution alone are not independent quality validation.

If a pack misses the floor, investigate tokenization, conversion and decoding against the reference. Evaluate an alternative checkpoint or record an explicit scope decision before release acceptance; never improve the score by selecting easier rows after seeing results.

Reproduce with Python 3.12, `sacrebleu==2.5.1 ctranslate2==4.6.0 sentencepiece==0.2.1` in a research-only environment. Acquire the fixtures with `scripts/research/fetch-flores-fixtures.py <external-fixture-directory>`. With the pinned verified model folders and acquisition receipts in an external model root, run `scripts/research/score-native-translation.py --helper <built-EarmarkNLLBWorker> --model-root <external-model-root> --fixtures <external-fixture-directory> --output <external-report.json> --family opus --reference-float32`. Model acquisition identities and per-file checksums are in the checkpoint inventory and aggregate quality report. Runtime decoding and semantic tests live in NLLBNative; the six-pack worker/lifecycle test lives in Translation. No Python or corpus is bundled with the app.

## Generative translator screening

The native Hy-MT2 1.8B/7B and TranslateGemma 4B/12B helpers use the same 30 frozen row indices for en↔de/fr/es/ja/zh. Run each profile serially, on its pinned GGUF, using the real model tokenizer and greedy decoding with the bounded profile prompt (4096 context, 1024 output maximum; input at most 3072 Hy-MT or 2048 Gemma tokens). Acquisition receipts, helper digests, every hypothesis, metric signatures and elapsed time remain in external reports. No network requests are made by inference.

The script records a deliberately conservative **screen**, not release acceptance: no empty/failed result, chrF++ ≥35 and all shared integer spellings retained. A low non-Latin score or changed number spelling triggers review; it cannot by itself establish semantic failure. Do not infer universal language support, equivalent quality across scripts, quantization parity or adequate Live latency from this screen. Full precision comparison, authored semantic cases, actual app flows, memory, cancellation and packaging remain separate requirements. Model selection and samples cannot be changed to improve a result after scoring.

The initial TranslateGemma profiles restrict advertised language bases to the published WMT24++ target cohort (plus English). The larger data-only chat template accepts more tags than that cohort. Those tags alone do not establish translation quality. In particular, Sinhala is excluded: preliminary 4B outputs mixed scripts and changed the meaning of a FLORES sentence. The 12B Sinhala direction has not been evaluated; its exclusion is a conservative coverage boundary, not a measured 12B failure. Hy-MT2 does not advertise Sinhala either.
